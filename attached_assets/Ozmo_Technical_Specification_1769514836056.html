Ozmo Technical Specification

Executive Summary

Ozmo is a full-stack web application providing a safe, curated YouTube viewing experience for children. It enables parents to manage child profiles, curate video libraries, control viewing sessions with time limits, and analyse viewing behaviour patterns.

Target Audience: Families with children ages 2-12 who want controlled YouTube access.

Core Value Proposition: Unlike YouTube Kids, Ozmo offers parent-curated content with automated playlist building, stimulation level tracking, session time limits, wind down protocols and analytics to monitor if your children’s TV schedule is effecting behaviour.

Core Algorithms

1. Playlist Generation Algorithm

The playlist builder creates age-appropriate content with stimulation wind-down.

function buildPlaylist(params: {
  children: Child[];
  availableMinutes: number;
  includeWindDown: boolean;
  timeOfDay: 'morning' | 'afternoon' | 'evening';
}): Video[] {
  const youngestAge = Math.min(...children.map(c => calculateAge(c)));

  // Filter videos by youngest child's age
  const ageAppropriateVideos = videos.filter(v =>
    v.ageMin <= youngestAge && v.ageMax >= youngestAge
  );

  // Determine max stimulation by time of day
  const maxStimulation = timeOfDay === 'evening' ? 3 : 5;

  // Separate regular (1-5) and calming (0) videos
  const regularVideos = ageAppropriateVideos.filter(v =>
    v.stimulationLevel >= 1 && v.stimulationLevel <= maxStimulation
  );
  const calmingVideos = ageAppropriateVideos.filter(v =>
    v.stimulationLevel === 0
  );

  // Build playlist with monotonic decrease
  const playlist = [];
  let remainingMinutes = availableMinutes;
  let currentMaxStim = maxStimulation;

  while (remainingMinutes > 0 && regularVideos.length > 0) {
    // Pick video at or below current max stimulation
    const candidates = regularVideos.filter(v =>
      v.stimulationLevel <= currentMaxStim
    );
    const video = randomPick(candidates);

    playlist.push(video);
    remainingMinutes -= video.durationSeconds / 60;
    currentMaxStim = video.stimulationLevel; // Enforce decrease
  }

  // Add calming videos if wind-down enabled
  if (includeWindDown) {
    playlist.push(...pickCalming(calmingVideos, 10)); // ~10 min calming
  }

  return playlist;
}

4. Video Catalog Diversification

Netflix-style rows avoid showing same channel repeatedly:

function diversifyVideos(videos: Video[], maxCount: number): Video[] {
  // Group by channel/series
  const groups = groupBy(videos, v => v.series || v.channelId);

  // Round-robin selection
  const result = [];
  let round = 0;

  while (result.length < maxCount) {
    for (const group of groups.values()) {
      if (group[round] && result.length < maxCount) {
        result.push(group[round]);
      }
    }
    round++;
  }

  return result;
}

5. Session Lifecycle

┌─────────────────────────────────────────────────────────────┐
│                    SESSION LIFECYCLE                         │
└─────────────────────────────────────────────────────────────┘

1. SESSION START
   Parent selects child(ren) → System calculates:
   - Available minutes (daily limit - already watched today)
   - Youngest child's age (for filtering)
   - Time of day (for stimulation caps)

2. PLAYLIST PREVIEW
   - Generate playlist with monotonic stimulation decrease
   - Show parent: videos, total duration, avg stimulation
   - Parent can: shuffle, replace videos, toggle wind-down

3. PLAYBACK
   - ChildWatch.tsx renders fullscreen player
   - YouTubePlayer component handles IFrame API
   - On video end: record to watch_history, advance to next
   - Auto-advance countdown (5s) for seamless transitions

4. SESSION END
   - Triggered by: last video ends OR parent clicks exit
   - PATCH /api/sessions/:id with endedAt
   - Calculate totalDurationSeconds from watch_history

5. FEEDBACK COLLECTION
   - Show emoji reactions for each video watched
   - Collect behavior rating (great/okay/upset/tantrum)
   - Store in session_feedback table
   - Update sensitivity recommendations

8. Embedding Error Detection

// Real-time detection in YouTubePlayer.tsx
function handleYouTubeError(event: YT.OnErrorEvent) {
  const errorCode = event.data;

  // Error 150 = embedding disabled by owner
  // Error 101 = video not embeddable
  if (errorCode === 150 || errorCode === 101) {
    // Report to server
    apiRequest('POST', `/api/videos/${videoId}/report-embed-error`);

    // Server-side: marks video as isHidden = 1
    // Creates admin notification

    // Client: skip to next video in playlist
    onError(errorCode);
  }
}

9. Time-of-Day Stimulation Caps

function getMaxStimulationForTime(): number {
  const hour = new Date().getHours();

  // Morning (6am - 12pm): Full range
  if (hour >= 6 && hour < 12) return 5;

  // Afternoon (12pm - 5pm): Slight reduction
  if (hour >= 12 && hour < 17) return 4;

  // Evening (5pm - 9pm): Calming content prioritized
  if (hour >= 17 && hour < 21) return 3;

  // Night (9pm+): Very calming only
  return 2;
}

Implementation Workflows

Child Onboarding (3-Step Wizard)

Step 1: Profile Setup

  • Name, birth month/year, gender
  • Calculate age from birth date
  • If under 3: show warning that most content is 3+
  • Offer opt-in toggle: "Allow 3+ content" (sets ageRestrictionOverride)

Step 2: Show Preferences (Swipe Discovery)

  • Fetch 10 videos for age-appropriate discovery cards
  • Swipe right = like, left = dislike, up = skip
  • Store in show_preferences table
  • "Swipe More" button to load next batch
  • Influences playlist generation weighting

Step 3: Schedule Setup

  • Daily entertainment limit (minutes)
  • Sensitivity level: Low (1-3) / Medium (4-7) / High (8-10)
  • Sensitivity detection toggle (emoji feedback monitoring)
  • Finish mode: Hard (no content after limit) or Soft (calming only)

Playlist Preview Flow

1. Parent clicks "Start Session" on child card
2. System builds playlist based on:
   - Available time remaining today
   - Child age(s) - uses youngest for filtering
   - Time of day for stimulation caps
   - Show preferences for weighting

3. PlaylistPreview component displays:
   - Regular videos (stimulation 1-5)
   - Wind-down videos (stimulation 0)
   - Total duration, average stimulation

4. Parent actions:
   - Shuffle: re-randomize while keeping constraints
   - Replace video: swap individual video
   - Toggle wind-down: add/remove calming videos
   - Confirm: start session

5. Session created, navigate to /watch/:childId

Browse Collections Flow

1. Parent navigates to /browse
2. Child selector shows which children are watching
3. GET /api/video-catalog returns Netflix-style rows:
   [
     { collection: "From Your Subscriptions", videos: [...] },
     { collection: "Saved Videos", videos: [...] },
     { collection: "Educational Fun", videos: [...] },
     ...
   ]

4. Each collection applies its own filters (themes, age, stimulation)
5. Clicking video:
   - Plays selected video
   - Auto-queues remaining videos from that collection
   - Personalization actions available during playback

Authentication Flow

Production Flow (Firebase)

1. User clicks "Sign in with Google"
2. Firebase Auth handles OAuth flow
3. Firebase returns ID token
4. Client includes token in API requests: Authorization: Bearer <token>
5. Server verifies with Firebase Admin SDK
